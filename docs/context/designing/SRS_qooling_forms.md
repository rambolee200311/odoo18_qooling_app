## 0. 文档说明

### 0.1 本文档回答什么

本文档定义将 Qooling 中首期 Forms 能力迁移到 Odoo 时，系统在业务上必须提供的能力：

- 入库表单；
- 出库表单；
- 每周温度控制登记；
- Web 表单和 PDF 表单两种录入入口；
- PDA 和 Web 端手写签名；
- 按 Odoo 用户语言显示单一字段名和选择值；
- 表单填写、保存、查询和追溯；
- ADR、货物、装载和温度相关检查；
- 表单照片、备注和签名等现场证据；
- 异常和问题的业务留痕。

本文档不定义具体 Odoo 模型、字段类型、数据库结构、视图 XML、ACL、Record Rule、菜单技术实现或前端组件实现。

## 1. 业务背景与目标

### 1.1 业务背景

PANEX WD Europe 当前在 Qooling 中使用多类运营、安全和合规表单。仓库人员通过 Qooling 完成入库、出库、ADR、装载、温度和相关安全检查。

项目目标是将首期 Forms 能力迁移并整合到 Odoo，使仓库操作人员可以在 Odoo 中完成业务检查，管理人员可以查询、追溯和跟进结果。

### 1.2 当前问题

- Qooling 表单与 Odoo 仓库业务记录分离；
- 入库、出库、温度和安全检查结果难以与 Odoo 业务对象统一追溯；
- ADR、装载问题、包装损坏和温度异常需要独立留痕；
- 需要减少在多个系统之间重复录入和查询；
- 现有表单中包含业务检查项，但这些检查项尚未成为 Odoo 中的统一业务记录。

### 1.3 业务目标

- 仓库人员能够在 Odoo 中完成首期入库、出库和每周温度控制表单；
- 表单结果能够按日期、执行人和相关业务参考查询；
- ADR 和危险品相关检查结果能够被明确记录；
- 出库检查能够覆盖货物、装载和车辆 ADR 标志；
- 每周温度控制能够记录每个托盘的温度；
- 异常回答能够触发后续问题处理或人工跟进；
- 关键表单记录能够保留操作人和操作时间。

本草稿不虚构效率、准确率或耗时百分比指标。

### 1.4 顶层产品约束

- **业务约束 1：表单结果必须可追溯**  
  → 每条记录必须能够识别表单类型、执行时间和执行人。
- **业务约束 2：危险品检查不得被隐含跳过**  
  → ADR 相关问题必须明确记录“是/否”或适用状态。
- **业务约束 3：异常不能被正常结果掩盖**  
  → 发现损坏、泄漏、温度异常或其他问题时，必须保留异常事实并支持后续处理。
- **业务约束 4：表单应服务于实际仓库流程**  
  → 入库、出库和温度记录必须能在仓库现场完成，不要求用户理解系统内部实现。
- **业务约束 5：表单标签和选项必须适配用户语言**  
  → Odoo 界面不得把荷兰语、英语和中文并列显示；用户应按自己的 Odoo 语言看到对应的字段名和选择值。

## 5. 功能需求

### 5.1 通用表单能力

#### FR-FORM-01 创建表单记录

**触发条件：** 授权仓库人员需要执行入库、出库或每周温度控制检查。  
**业务行为：** 库管人员选择表单类型并创建一条新的检查记录。
**业务结果：** 系统生成一条可填写的草稿记录，并记录表单类型。  
**异常/边界：** 未授权用户不得创建；无法识别表单类型时不得生成记录。

#### FR-FORM-02 记录执行信息

**触发条件：** 用户开始填写表单。  
**业务行为：** 系统自动记录日期/时间和当前用户，用户可以修改日期/时间，并填写相关业务参考。
**业务结果：** 表单具备可追溯的执行上下文。  
**异常/边界：** 执行时间和执行人缺失时，不得提交需要追溯的表单。

#### FR-FORM-03 保存草稿

**触发条件：** 用户已填写部分表单，需要暂存或稍后继续。  
**业务行为：** 用户保存当前内容；草稿可以反复修改。
**业务结果：** 草稿内容可被重新打开并继续填写。  
**异常/边界：** 保存失败时不得显示为成功；已保存内容不得被静默丢失。

#### FR-FORM-04 提交表单

**触发条件：** 用户完成必填检查项。  
**业务行为：** 用户完成必填项和签名后提交表单；仓库主管可以复核。
**业务结果：** 表单进入已提交状态，并保留提交人和提交时间。  
**异常/边界：** 必填项或签名缺失时不得提交；具体检查阻断项按各表单规则确定。

#### FR-FORM-05 查询历史记录

**触发条件：** 授权用户需要检查历史表单或追溯业务事实。  
**业务行为：** 用户按表单类型、日期、执行人或相关参考查询记录。  
**业务结果：** 系统展示符合条件的记录及其状态。  
**异常/边界：** 用户只能查看其权限范围内的记录。

#### FR-FORM-06 Web 入口录入和提交

**触发条件：** 用户通过 Odoo Web 入口执行任一首期表单。  
**业务行为：** 用户在 Web 中录入、保存草稿、提交表单，并由授权仓库主管复核。  
**业务结果：** Web 录入结果进入与 PDF 录入相同的业务记录、状态和复核流程。  
**异常/边界：** Web 不得省略 PDF 版本要求的业务字段、签名或提交信息。

#### FR-FORM-07 PDF 入口录入和提交

**触发条件：** 用户需要通过 PDF 文件完成任一首期表单。  
**业务行为：** 用户填写对应 PDF 表单并提交；系统或授权人员将 PDF 中的字段、签名、附件和归档信息登记到该表单业务记录。  
**业务结果：** PDF 录入结果可进入草稿、已提交和复核流程，并与 Web 录入记录使用同一业务字段语义。  
**异常/边界：** PDF 字段无法识别、缺少必填字段或缺少必需签名时，不得伪造为已提交；应保留失败原因并允许人工处理。

#### FR-FORM-08 Web/PDF 统一复核

**触发条件：** Web 或 PDF 表单已提交。  
**业务行为：** 仓库主管在统一的复核流程中查看表单字段、来源入口、附件、签名和人工检查结果，并执行复核。  
**业务结果：** 无论来源是 Web 还是 PDF，表单均可被查询、复核、撤回和追溯。  
**异常/边界：** Web 与 PDF 对同一字段的含义、必填性、状态流转和权限不得不一致。

#### FR-FORM-09 多语言字段和选择值

**触发条件：** 用户打开、录入、提交或复核任一首期表单。  
**业务行为：** 系统根据当前 Odoo 用户语言显示字段名、帮助文本和选择值；同一界面只显示当前语言版本，不并列显示多种语言。  
**业务结果：** 不同语言用户可以使用相同业务字段和选择值完成录入、提交和复核。  
**异常/边界：** 若某语言缺少翻译，应按 Odoo 多语言回退规则显示，不得把三种语言拼接成一个标签或选择值。

#### FR-FORM-15 PDA/Web 手写签名

**触发条件：** 用户通过 PDA 或 Web 完成任一首期表单并准备保存或提交。  
**业务行为：** 用户在 PDA 或 Web 的签名区域直接手写绘制签名；系统保存签名图像，并将其与表单、签名人和签名时间关联。  
**业务结果：** 三类表单均可在 PDA 和 Web 端完成手写签名；签名作为提交条件和复核证据保留。  
**异常/边界：** 未完成手写签名时不得保存为已完成或提交；姓名文本、用户名称自动带出、勾选确认或键盘输入不得替代手写签名。

### 5.2 Inbound Form

#### FR-FORM-10 记录入库参考

**触发条件：** 入库装载完成后，仓库人员填写 Inbound Form。  
**业务行为：** 用户填写日期/时间、仓库操作员、主管、地点、B/L、MRN 编号、密封编号、集装箱号或发运号等入库参考。地点来自仓库档案并必填；模板还包含表单编号、填写日期和填写人。客户字段不作为本模板的确认字段。
**业务结果：** 入库检查与对应货物/容器形成关联。  
**异常/边界：** 无法确认关联业务参考时，必须允许保存草稿但不得提交，除非业务确认该字段非必填。

#### FR-FORM-11 记录入库托盘

**触发条件：** 入库表单需要记录收货托盘。  
**业务行为：** 用户记录托盘数量、纸箱数量及每个托盘相关的收货检查信息，包括批次/批号、数量、标签可读性和包装状态。包装状态为 `Good` 或 `Not good`；`Not good` 时停止卸货并联系项目经理获取进一步指示。
**业务结果：** 表单保留每个托盘的入库检查结果。  
**异常/边界：** 托盘数量与实际收货不一致时，应允许记录差异或异常。

#### FR-FORM-12 记录入库产品属性

**触发条件：** 用户检查入库货物。  
**业务行为：** 用户记录货物状态、是否已获得卸货许可、是否为 BIO/SKAL 产品、是否为 ADR 货物，并在适用时选择 UN 编号。货物状态固定为 Free union goods 和 T1；SKAL/BIO 固定为 Yes/No；以上字段必填。卸货许可为 No 时，应停止卸货并联系项目经理。
**业务结果：** 表单明确记录产品和危险品属性。  
**异常/边界：** ADR 选择为“是”时，UN 编号必须填写；非 ADR 时不得要求无关的危险品信息。

#### FR-FORM-13 记录入库温度

**触发条件：** 入库检查要求测量货物或托盘温度。  
**业务行为：** 用户记录是否已测量温度、每个托盘是否已登记温度和每个托盘的平均温度。温度测量相关选择为 Yes/No；温度数值、单位和阈值由用户按业务规则录入。
**业务结果：** 入库记录保留温度事实和异常情况。  
**异常/边界：** 未执行温度检查时，不能将表单标记为温度检查完成；温度单位固定为摄氏度。测量次数、范围和阈值由人工复核决定，系统只记录用户结果，不自动判断。

#### FR-FORM-14 记录入库气体和通风检查

**触发条件：** 入库货物或集装箱需要进行气体测量或通风检查。  
**业务行为：** 用户记录气体测量是否执行（Yes/No/Not Applicable）、测量状态、是否通风以及通风后的状态。模板同时包含一个未展开的 Checkbox list，具体检查项和选项尚未从该 Word 模板确定。
**业务结果：** 气体和通风事实可追溯，用户不能用空白值代替检查结果。  
**异常/边界：** 测量或通风结果异常时必须保留异常事实；具体阻断条件待确认。

### 5.3 Outbound Form

#### FR-FORM-20 记录出库参考和装载时间

**触发条件：** 出库装载完成后，仓库人员填写 Outbound Form。  
**业务行为：** 用户填写发运号/参考号、到达日期/时间、开始装载时间和结束装载时间，并记录 MRN 编号、封条编号以及放行前是否已核查 MRN。
**业务结果：** 出库检查与对应发运活动建立关联。  
**异常/边界：** 到达时间、开始装载时间和结束装载时间必填，并满足到达时间 ≤ 开始装载时间 ≤ 结束装载时间。MRN 和封条为非必填文本字段。

#### FR-FORM-21 检查货物和包装

**触发条件：** 出库装载检查开始。  
**业务行为：** 用户检查可见损坏、包装状态、正确标识、货物是否固定、数量和包装/货物是否符合装载要求。
**业务结果：** 货物检查结果被明确记录；模板将检查划分为 Cargo inspection、Vehicle inspection 和 Driver check 三类检查上下文。
**异常/边界：** 发现异常时不得被记录为正常；应保留异常描述或进入问题跟进。

#### FR-FORM-22 检查装载过程

**触发条件：** 出库装载检查开始。  
**业务行为：** 用户核对装载计划、是否已与司机讨论装载计划、ADR 分离/兼容性、重量分布、装载数量、货物固定和车辆前部 ADR 橙色标志，并记录司机备注和司机签名确认。装载计划与司机讨论不强制为 Yes；ADR 分离/兼容性字段不因非 ADR 自动隐藏。
**业务结果：** 装载检查项形成完整结果。  
**异常/边界：** 司机手写签名为必填，缺少签名时不能保存；任一其他阻断性检查未完成时不得提交。其他检查是否阻断由人工复核决定，系统只记录检查结果。

#### FR-FORM-23 记录出库 ADR

**触发条件：** 出库货物可能属于 ADR 危险品。  
**业务行为：** 用户选择 ADR 是/否；ADR 为 Yes 时显示并要求填写 UN Number 和温度测量相关字段，ADR 为 No 时隐藏这些字段。
**业务结果：** 出库表单明确记录 ADR 状态。  
**异常/边界：** ADR 为“是”时，必须完成对应危险品检查；UN 编号仅允许 `3171`、`3480`、`3481`；Proper Shipping Name 手工填写；非 ADR 时仍显示 ADR 分离/兼容性字段。

#### FR-FORM-24 上传装载照片

**触发条件：** 出库表单要求装载照片。  
**业务行为：** 用户上传装载现场照片。  
**业务结果：** 照片与出库表单关联并可追溯。  
**异常/边界：** 上传失败时不得显示为成功；照片为非强制字段。

#### FR-FORM-25 检查车辆和装载工具

**触发条件：** 出库装载检查开始。  
**业务行为：** 用户记录货物固定材料、反光安全背心、护目装置、防护手套、止轮块、防水布、手电筒、铲子、滴水盘、洗眼瓶和两个独立警示三角牌等检查结果。  
**业务结果：** 车辆和装载工具检查结果与出库表单关联。  
**异常/边界：** 任一检查项不符合要求时必须保留不符合事实；是否阻止提交由人工复核决定，系统只记录检查结果。

#### FR-FORM-26 记录出库归档信息

**触发条件：** 出库检查完成并准备归档。  
**业务行为：** 用户记录货物照片、仓库操作员备注、仓库操作员手写签名、填写人、归档日期和表单编号。照片和备注非必填；仓库操作员签名为必填。
**业务结果：** 出库检查的现场证据、责任确认和归档信息与表单关联。  
**异常/边界：** 仓库操作员签名为必填，缺少签名时不能保存；照片和备注非必填；上传或保存失败不得显示为成功。

### 5.4 Weekly Temperature Control

#### FR-FORM-30 创建周度温度记录

**触发条件：** 到达每周温度控制周期。  
**业务行为：** 用户创建 Weekly Temperature Control 记录。  
**业务结果：** 系统生成带有执行日期/时间、执行人的温度检查记录。  
**异常/边界：** 同一业务范围和周期是否允许多条记录待确认。

#### FR-FORM-31 记录温度检查上下文

**触发条件：** 用户开始每周温度检查。  
**业务行为：** 用户记录日期/时间、经理、客户、集装箱号、执行人和适用地点等上下文信息。经理从用户中选择；客户和集装箱号必填。当前业务记录频率为每天。
**业务结果：** 温度记录可以与对应业务和责任人关联。  
**异常/边界：** 业务将该记录称为每周温度控制，但当前实际记录频率为每天；周期提醒和重复记录规则仍需统一。

#### FR-FORM-32 记录每个托盘温度

**触发条件：** 温度检查覆盖多个托盘。  
**业务行为：** 用户动态记录实际托盘及其温度，并记录总托盘数。原 Qooling 模板固定展开至 `Pallet 65`；在 Odoo 中不固定 65 个托盘，超过 65 个托盘时创建新记录。
**业务结果：** 每个托盘具有独立温度记录。  
**异常/边界：** 缺失任一要求检查的托盘温度时，不得提交为完整记录。

#### FR-FORM-33 记录温度异常

**触发条件：** 检查发现温度异常、货物损坏或电解液泄漏。  
**业务行为：** 用户记录包装是否有可见损坏、未包装产品壳体是否有可见损坏、存储是否稳定、是否存在电解液泄漏和电池温度异常，并按照业务要求创建或关联问题。
**业务结果：** 异常事实被保留，相关人员可以继续处理。  
**异常/边界：** 异常不能被覆盖为“正常”；异常处理路径和责任人待确认。

#### FR-FORM-34 记录温度异常处置

**触发条件：** 单个托盘或集装箱温度超过业务阈值。  
**业务行为：** 用户记录隔离、复测或其他处置结果。截图中的业务指引要求电池温度超过 `40°C` 时隔离；多个托盘异常时，可将托盘放到集装箱外适应环境约 20 分钟后重新测量，复测仍异常的托盘应隔离。  
**业务结果：** 原始温度、复测温度和处置结果均保留，不能仅以复测结果覆盖原始异常。  
**异常/边界：** `40°C` 阈值、20 分钟时长以及单托盘/多托盘判定规则需业务确认后才能冻结。

#### FR-FORM-35 记录表单证据

**触发条件：** 用户需要补充现场证据或完成表单。  
**业务行为：** 用户可按表单要求添加照片、备注和签名；模板还包含图片、填写人、填写日期和表单编号等归档信息。
**业务结果：** 证据与表单记录关联，并在重新打开记录时仍可查看。  
**异常/边界：** 附件上传失败不得显示为成功；照片非必填，签名按手写签名要求执行。

## 6. 业务规则

| 编号 | 规则描述 | 作用级别 | 关联需求 |
|---|---|---|---|
| `BR-FORM-01` | 已提交表单必须保留执行人和执行时间 | 阻断 | `FR-FORM-02`, `FR-FORM-04` |
| `BR-FORM-02` | 草稿可以继续编辑，已提交记录的修改规则必须受控 | 阻断 | `FR-FORM-03`, `FR-FORM-04` |
| `BR-FORM-03` | ADR 为“是”时必须完成适用危险品检查 | 阻断 | `FR-FORM-12`, `FR-FORM-23` |
| `BR-FORM-04` | ADR 相关表单应支持 UN 编号记录，首期至少覆盖 `3171`、`3480`、`3481` | 阻断 | `FR-FORM-12`, `FR-FORM-23` |
| `BR-FORM-05` | 发现包装、货物、车辆、固定或温度异常时，结果不得被标记为全部正常 | 阻断 | `FR-FORM-21`, `FR-FORM-22`, `FR-FORM-33` |
| `BR-FORM-06` | 每周温度控制应能记录每个托盘的温度 | 阻断 | `FR-FORM-32` |
| `BR-FORM-07` | 表单结果必须可按类型、日期和执行人追溯 | 应 | `FR-FORM-05` |
| `BR-FORM-08` | 上传的装载照片必须与出库表单关联 | 应 | `FR-FORM-24` |
| `BR-FORM-09` | 电池温度超过 `40°C` 时必须记录隔离或经确认的异常处置 | 阻断 | `FR-FORM-33`, `FR-FORM-34` |
| `BR-FORM-10` | 多个托盘温度异常时，复测前应记录约 20 分钟的外部适应过程；复测仍异常的托盘必须隔离 | 应 | `FR-FORM-34` |
| `BR-FORM-11` | 业务异常必须保留原始检查结果、异常说明和处置结果 | 阻断 | `FR-FORM-21`, `FR-FORM-33`, `FR-FORM-34` |
| `BR-FORM-12` | 入库气体测量和通风结果必须明确记录 Yes/No/Not Applicable 或对应状态 | 应 | `FR-FORM-14` |
| `BR-FORM-13` | Weekly Temperature Control 必须分别记录包装损坏和未包装产品壳体损坏 | 应 | `FR-FORM-33` |

### 6.1 业务异常 vs 基础设施异常

| 类型 | 示例 | 业务处理 |
|---|---|---|
| 业务异常 | ADR 信息缺失、包装损坏、温度异常、托盘温度缺失 | 保留异常结果，转人工处理或问题跟进 |
| 基础设施异常 | 保存失败、附件上传失败、系统不可用 | 不得伪造成功，保留可重试或人工补录路径 |

## 7. 状态与生命周期

### 7.1 状态定义

| 状态 | 业务含义 | 可进入条件 | 可执行动作 |
|---|---|---|---|
| 草稿 | 表单已创建但未提交 | 创建表单 | 填写、保存、修改、提交 |
| 已提交 | 表单已完成提交 | 满足提交条件 | 查看、复核、跟进 |
| 异常待处理 | 表单存在需要处理的异常 | 检查结果异常或提交后发现问题 | 查看、关联问题、跟进 |
| 已关闭 | 异常已完成业务处理 | 责任人完成处理并确认 | 查看历史 |

“已关闭”是否属于本期，以及异常是否自动进入“异常待处理”，待确认。

### 7.2 状态流转

| 当前状态 | 动作/条件 | 目标状态 | 关联需求 |
|---|---|---|---|
| — | 创建表单 | 草稿 | `FR-FORM-01` |
| 草稿 | 保存 | 草稿 | `FR-FORM-03` |
| 草稿 | 满足提交条件并提交 | 已提交 | `FR-FORM-04` |
| 已提交 | 授权用户撤回 | 草稿 | `BD-06` |
| 草稿 | 检查发现异常 | 异常待处理或草稿 | `FR-FORM-33` |
| 已提交 | 发现或登记异常 | 异常待处理 | `FR-FORM-33` |
| 异常待处理 | 完成处理 | 已关闭 | 待确认 |

### 7.3 禁止流转

- 未完成必填或阻断性检查时，禁止从草稿进入已提交；
- ADR 为“是”但危险品检查未完成时，禁止提交；
- 缺少每个托盘温度时，禁止将周度温度记录标记为完整；
- 已提交记录不得无审计地直接覆盖原始检查结果；
- 异常记录不得被静默删除。
- 温度异常的原始读数不得被复测读数无审计地覆盖。
